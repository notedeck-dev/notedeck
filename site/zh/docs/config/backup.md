# 备份

## 要保护的是什么

NoteDeck 持有的数据分为两部分。

| | 内容 | 位置 |
|---|---|---|
| **设置与记录** | 列配置、主题、快捷键、插件、备忘、AI 的人格与记忆等 | 应用数据文件夹中的 [`config/` 与 `data/`](/zh/docs/config/files#设置在哪里) |
| **帖子缓存** | 刷过的帖子的存档、账户信息 | 应用数据文件夹下的 `notecli.db` |

访问令牌和 AI 的 API 密钥都不在这两者之中（因为它们在操作系统的钥匙串中）。在迁移目标上需要重新登录。

## 从应用内获取

在设置菜单的**备份**（バックアップ）中，可以把帖子缓存和设置一起导出，并读回。导出位置是下载文件夹中的 `notedeck/backup/<日期时间>/`，旧的会保留一定数量后删除（“打开备份文件夹”会打开该位置）。帖子缓存即使在运行中也会以一致的状态复制，认证信息始终会被移除。

同样的事也可以交给 AI 来做（capability `backup.create`。由于影响较大，默认关闭，来自外部的请求始终被拒绝）。

## 备份设置

设置支持导出 / 导入。在另一台电脑上导入导出的文件，就能重现相同的环境。

对象是[设置文件](/zh/docs/config/files#config-里有什么)中列出的 `config/` 的内容，以及 `data/` 中的备忘、AI 的对话和人格与记忆的 3 个 Markdown。这台电脑的状态（`state/`：窗口位置、同意、教程完成记录等）和编辑历史不会纳入。插件和小工具用 `Mk:save` 保存的值也不会纳入。

如果想让设置与另一台电脑持续保持一致，[用 Git 管理](/zh/docs/config/sync)比备份更合适。

导入会覆盖当前的设置并重启。内容相同的会跳过，名称冲突的以别名导入，名称不合法的不会导入。是否替换人格与记忆会单独确认。

## 备份帖子

使用应用内的备份最为可靠。手动备份的话，**只需复制** `notecli.db`。这是一个 SQLite 文件，仅这一个文件就完整包含了存档的帖子和账户信息。手动复制时请在退出应用后进行。在应用运行时复制，可能会拿到写入到一半的状态。

::: warning 删除后无法恢复
即使卸载应用，设置和缓存也会保留；但如果删除整个应用数据文件夹，存档的帖子也会一起消失。能从服务器重新获取的，只有服务器上仍然存在的内容。
:::

## Misskey 端的数据

自己的帖子、关注、收藏等存放在服务器上的数据，其备份属于 Misskey 端的功能。请从服务器的设置页面导出。NoteDeck 的备份保存的仅仅是“这台设备的状态”。
