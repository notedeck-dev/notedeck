# 与 AI 一起使用

NoteDeck 可以接入 AI，但**是否使用完全由你决定**。只有接入 AI 提供商的 API 密钥、或把本地 CLI 用作 AI 时才会启用，不接入时其他功能也都能正常使用。

应用本身没有代你支付 AI 使用费的机制。费用由你签约的提供商直接收取。

AI 的本体（智能体循环和 HEARTBEAT）运行在独立于应用的进程中。平时无需在意，机制请参阅 [AI 的独立进程](/zh/docs/notemaid)。

## 接入

1. 在设置菜单的**连接**（接続）中登记提供商的 API 密钥
2. 在设置菜单的**智能体**（エージェント）中选择已登记的连接

Anthropic、OpenAI、xAI、Google、OpenRouter 和 OpenCode Go 已内置模板，只需选择并粘贴 API 密钥即可接入。

支持 **Anthropic Messages 兼容**和 **OpenAI Chat Completions 兼容**两种格式。即使是模板中没有的服务，比如自建的 LLM 网关，只要使用其中一种格式，就可以手动登记并接入。

API 密钥保存在操作系统的钥匙串中。它不会写入设置文件，插件和 AI 本身也无法读取其内容。

### 把本地 CLI 用作 AI

可以不用 API 密钥，而是把本机上已安装并已登录的 AI CLI（Claude Agent (Claude Code) / Codex / OpenCode / Hermes Agent / Grok Build）直接用作 AI。在连接中选择“本地 CLI”（手元の CLI），就会列出找到的 CLI。

- 来自 CLI 的许可请求会作为聊天的确认对话框显示。权限由“AI 聊天”那一行决定
- “关于你的记忆”默认也会传给 CLI。不想传的话，请关闭“记忆”（メモリー）中的“也传给本地 CLI”（会被发送到 CLI 的提供方，并可能留在 CLI 自身的记忆中）
- HEARTBEAT 不会通过这条路径运行

## 能做什么

除了在 AI 列中对话，还可以直接从帖子菜单把帖子交给 AI（摘要、翻译等）。

AI 也能操作应用。添加列、切换账户、制作主题、修改快捷键 — 都可以在对话中提出。AI 操作过的位置会在界面上高亮显示，让你知道发生了什么。

发帖、回应等**影响外部的操作之前，一定会弹出确认对话框**。不会擅自发帖。

## 决定让它看到什么

传给 AI 的信息可以在设置中选择。

- 当前使用的账户
- 打开的列
- 界面上可见的帖子
- 对话历史

不需要的可以关闭。

备忘不会一直传给 AI。AI 延续下去的记忆在“记忆”（メモリー，见下文）中，具体的备忘由 AI 在需要时搜索并读取。

## 人格与记忆

AI 拥有切换角色也不会改变的**人格**，以及两种记忆。在智能体设置的“人格设定”（ペルソナ）和“记忆”（メモリー）中可以随时查看。

- **人格**（人格设定）：价值观、边界和语气的核心。AI 不会自行改写，而是提出建议并等待你的批准。直接编辑正文要在开发者模式的标签页或外部编辑器中进行
- **关于你的记忆**（记忆）：称呼方式、说话风格偏好等你在对话中告诉它的内容。可以逐行修改或删除。关闭“记住关于我的事”（あなたのことを覚える）后，既不会传给 AI，也不会记住新的内容（“全部忘记”是另一个操作）
- **笔记**（记忆）：AI 自己捕捉到的小事实和做出的决定。可以逐行修改或删除

AI 行为的指导方针写在同一界面的“规则”（ルール）中。语气和角色设定可以通过[技能](/zh/docs/dev/skill)的“角色”（キャラクター）更换，人格在切换技能后依然保留。

第一次打开 AI 列时，可以从“告诉它怎么称呼你”开始。AI 会和你一起决定它自己的名字和氛围，只会询问该怎么称呼你。如果你不提，它不会主动问。

写入记忆时，如果刚读过他人的帖子，一定会弹出确认。确认中会附上读了哪些帖子，以及要写入的文字是否原样出现在他人的帖子中。对人格的提议每次都需要批准，不能省略。在看家（HEARTBEAT）期间不会写入记忆。

## 权限

AI 能做什么由权限设置控制。默认设置较为保守，以读取为主。

权限按用途相互独立。聊天中的 AI 与后文 HEARTBEAT 中运行的 AI 可以分别设置，放宽其中一个不会影响另一个。插件和外部应用的行也在同一界面中。

## 你不在时运行（HEARTBEAT）

这是定期运行 AI 的机制。可以让它帮你盯着，比如“如果新通知里有什么重要的，就告诉我”。在智能体设置的 HEARTBEAT 中启用，并通过“编辑巡查步骤”（巡回の手順を編集）写下要做什么。

- 没有需要报告的内容时，它会保持沉默
- 结果会累积在指定的会话中。AI 标记为“请通知”的报告、等待确认的操作、自动停止，也会留在**应用的通知**（收件箱）中，点击即可打开对应的界面
- 打开“先轻量检查”（まず軽く確認）后，自上次以来没有变化期间就不会调用 AI
- 可以为每天的 AI 启动次数设置上限，达到上限后自动停止
- 连续失败时会自动停止并发出警告（以免在你不知情的情况下一直出错）

基本上只在应用运行期间运行。打开“退出应用后继续运行”（アプリを終了しても続ける）后，[AI 的独立进程会常驻](/zh/docs/notemaid#设为常驻)，关闭期间的报告会在下次打开应用时汇总为一条送达。

由于是无人值守运行，它的权限与聊天分开设置，默认也更严格。无人期间不会写入记忆，需要确认的操作不会执行，而是作为“稍后确认再执行”的卡片留在报告目标会话中。

::: warning 注意一直运行的成本
HEARTBEAT 会定期调用 API。请先确定间隔和权限再启用。也可以为每个连接设置每天的 token 预算。
:::

## 从外部 AI 智能体使用（MCP）

反过来，也可以让 Claude Code、Claude Desktop 等外部 AI 智能体把 NoteDeck 当作工具使用。NoteDeck 内置了 MCP（Model Context Protocol）服务器，会把搜索帖子、发帖等与 AI 聊天相同的 capability 作为 tool 提供。

1. 在设置 → 权限 →“永久 API 令牌”（永続 API トークン）中签发令牌。签发后的界面会显示 Claude Code 用的注册命令和 Claude Desktop 用的配置 JSON，复制所需的那一个
2. 外部可使用的范围，由同一界面中“外部应用”（外部アプリ）的权限决定。默认只能读取，发帖等写入操作需要逐项允许
3. 写入操作一定会先在 NoteDeck 的界面上确认后才执行。外部 AI 不会擅自发帖

像 Claude Code 这样通过 HTTP 连接的应用，直接连接 `http://127.0.0.1:19820/mcp`。像 Claude Desktop、Cline 这样通过 stdio 启动服务器的应用，把内置的 `notemaid` 作为 `notemaid mcp` 交给它们，就会转发到正在运行的 NoteDeck。两种方式都只在 NoteDeck 运行期间可用。
