# 故障排除

遇到问题时，请先查看**关于 NoteDeck**（NoteDeck について / About）窗口中的“自我诊断”（自己診断）。流的断开、上次的异常退出、AI 独立进程的状态、HEARTBEAT 的连续失败都会汇总显示在这里。用“复制信息”（情報をコピー）可以获取用于报告的信息。

## 无法登录

输入服务器的主机名（格式如 `misskey.io`。即使带上 `https://` 或末尾的 `/` 也会被自动去掉）。

认证通过浏览器进行。在浏览器中允许后，直到你点击 NoteDeck 侧的“已认证”（認証しました）才算完成。如果默认浏览器没有打开，或者中途不知道该怎么办了，请用“重试”（やり直す）从头再来。

在没有 Secret Service（GNOME Keyring 等）的 Linux 环境下，启动时会显示相应的警告，令牌会转存到加密文件中。

## 时间线不再更新

NoteDeck 通过 WebSocket 与服务器保持连接。网络断开或刚从睡眠中恢复后，重新连接需要一点时间。

等待一段时间后仍然没有新内容时：

1. 确认**离线模式**或实时模式没有被关闭（也可以从托盘菜单切换）
2. 确认“窗口隐藏期间暂停时间线的订阅”设置没有在起作用
3. 手动刷新该列
4. 在 About 的自我诊断中查看连接状态。要进一步追查，可在[开发者模式](/zh/docs/#开发者模式)下打开**流**（ストリーム）列，检查正在传输的事件

流列会原样显示实际的通信内容，因此可以判断是“服务器没有发来”，还是“应用没有显示”。

## 帖子不显示或突然消失

帖子不显示有几种原因。

- **被屏蔽规则命中** — 检查关键词、用户、服务器和转发的屏蔽设置
- **被列查询筛掉** — 在列的筛选菜单中检查正在应用的查询
- **发帖者被冻结** — 在服务器上被冻结的用户的帖子会被隐藏。解除冻结后会自动恢复显示

NoteDeck 不会删除数据，只是判断“是否显示”。解除屏蔽后，被隐藏的帖子会原样恢复。

## 图片不显示、无法使用外部联动

如果启动时提示“无法使用图片中继和外部联动（HTTP API）”，说明 NoteDeck 使用的本地端口已被其他应用先占用。请停止那个应用，或腾出端口后重新启动 NoteDeck。

## 显示错乱

如果你写了 `custom.css`，请先清空其内容再确认。应用更新改变了内部结构时，以前写的 CSS 可能会作用到意料之外的地方。

也可能是主题造成的。请切换回默认主题来排查。

## 运行缓慢

- 减少打开的列的数量（用[配置文件](/zh/docs/deck/profiles)按用途分开）
- 把[显示的轻重](/zh/docs/guide/appearance#选择显示的轻重)改为偏向省内存的预设
- 关闭图片较多的列

## AI 没有回应

- API 密钥是否有效，提供商那边是否还有余额
- 智能体设置中是否已选择提供商
- 所需操作是否被权限禁止（是否不小心关掉了确认对话框）
- AI 的独立进程是否在运行。About 的自我诊断中会显示子进程已退出、版本不一致、常驻未运行等原因。详情请参阅 [AI 的独立进程](/zh/docs/notemaid#遇到问题时)

HEARTBEAT 连续失败时会自动停止并发出警告。请修复原因后再重新启用。

## 想把设置恢复为初始状态

删除对应的[设置文件](/zh/docs/config/files)后，下次启动时会以默认值重新生成。如果想全部恢复，请删除整个设置文件夹。

::: warning 请先备份
删除设置文件夹时，备忘、AI 的人格与记忆、AI 会话、技能、插件、主题也会一起消失。请先进行[备份](/zh/docs/config/backup)。存档的帖子（`notecli.db`）位于设置文件夹的上一级，所以会保留。
:::

## 仍然无法解决时

请在 [GitHub 的 Issues](https://github.com/notedeck-dev/notedeck/issues) 中报告。提供以下信息会更容易找到原因。

- 操作系统和应用的版本
- 做了什么之后发生
- About 自我诊断中“复制信息”的内容（异常退出之后则是“复制诊断日志并报告”）
- 日志（**文件 → 打开日志文件夹**（ファイル → ログフォルダを開く）。AI 独立进程的日志在应用数据文件夹的 `logs/` 中）
