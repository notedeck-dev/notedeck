# 故障排除

## 无法登录

请确认只输入了服务器的主机名（不需要 `https://`，格式如 `misskey.io`）。

认证通过浏览器进行。如果默认浏览器没有打开，或者允许后没有回到 NoteDeck，请先重启一次应用，然后重试。

## 时间线不再更新

NoteDeck 通过 WebSocket 与服务器保持连接。网络断开或刚从睡眠中恢复后，重新连接需要一点时间。

等待一段时间后仍然没有新内容时：

1. 手动刷新该列
2. 打开**流**（ストリーム）列，检查连接状态和正在传输的事件

流列会原样显示实际的通信内容，因此可以判断是“服务器没有发来”，还是“应用没有显示”。

## 帖子不显示或突然消失

帖子不显示有几种原因。

- **被屏蔽规则命中** — 检查关键词、用户、服务器和转发的屏蔽设置
- **被列查询筛掉** — 在列的筛选菜单中检查正在应用的查询
- **发帖者被冻结** — 在服务器上被冻结的用户的帖子会被隐藏。解除冻结后会自动恢复显示

NoteDeck 不会删除数据，只是判断“是否显示”。解除屏蔽后，被隐藏的帖子会原样恢复。

## 显示错乱

如果你写了 `custom.css`，请先清空其内容再确认。应用更新改变了内部结构时，以前写的 CSS 可能会作用到意料之外的地方。

也可能是主题造成的。请切换回默认主题来排查。

## 运行缓慢

- 减少打开的列的数量（用[配置文件](/zh/docs/deck/profiles)按用途分开）
- 把[显示的轻重](/zh/docs/guide/appearance#选择显示的轻重)改为偏向省内存的预设
- 关闭图片较多的列

## AI 没有回应

- API 密钥是否有效，提供商那边是否还有余额
- AI 设置中是否已选择提供商
- 所需操作是否被权限禁止（是否不小心关掉了确认对话框）

HEARTBEAT 连续失败时会自动停止并发出警告。请修复原因后再重新启用。

## 想把设置恢复为初始状态

删除对应的[设置文件](/zh/docs/config/files)后，下次启动时会以默认值重新生成。如果想全部恢复，请删除整个设置文件夹。

::: warning 请先备份
删除设置文件夹时，存档的帖子缓存和备忘也会一起消失。请先进行[备份](/zh/docs/config/backup)。
:::

## 仍然无法解决时

请在 [GitHub 的 Issues](https://github.com/notedeck-dev/notedeck/issues) 中报告。提供以下信息会更容易找到原因。

- 操作系统和应用的版本
- 做了什么之后发生
- 日志（**文件 → 打开日志文件夹**（ファイル → ログフォルダを開く））
