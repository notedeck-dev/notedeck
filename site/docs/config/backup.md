# バックアップ

## 何を守りたいか

NoteDeck が持っているデータは 2 つに分かれます。

| | 中身 | どこ |
|---|---|---|
| **設定** | カラム構成、テーマ、キーバインド、プラグイン、メモ、AI の人格と記憶など | [設定フォルダ](/docs/config/files#設定はどこにあるか) |
| **ノートのキャッシュ** | 流れてきたノートの蓄積、アカウント情報 | 設定フォルダの親にある `notecli.db` |

アクセストークンと AI の API キーはどちらにも入っていません（OS のキーチェーンにあるため）。移行先では改めてログインが必要です。

## アプリの中から取る

設定メニューの**バックアップ**で、ノートのキャッシュと設定をまとめて書き出し、読み戻せます。書き出し先はダウンロードフォルダの `notedeck/backup/<日時>/` で、古いものは一定数を残して消えます（「バックアップフォルダを開く」で場所が開きます）。ノートのキャッシュは起動中でも整合した状態で写され、認証情報は常に取り除かれます。

同じことを AI に頼むこともできます（capability `backup.create`。影響が大きいので既定ではオフで、外部からは常に拒否されます）。

## 設定のバックアップ

設定はエクスポート / インポートに対応しています。書き出したファイルを別のマシンで読み込めば、同じ環境を再現できます。

対象は[設定ファイル](/docs/config/files#何がどこに書かれるか)に挙げたファイルとフォルダのうち、`client.json5`（端末ごとの構成）を除いたものです。`notemaid/` からは人格と記憶の 3 つの Markdown だけが入ります。プラグインやウィジェットが `Mk:save` で残した値は入りません。

インポートすると現在の設定を上書きして再起動します。中身が同じものは飛ばし、名前が衝突したものは別名で入り、不正な名前のものは入れません。人格と記憶を置き換えるかどうかは個別に確認されます。

## ノートのバックアップ

アプリ内のバックアップを使うのが確実です。手で取るなら `notecli.db` を**コピーするだけ**です。SQLite のファイルなので、それ 1 つで蓄積したノートもアカウント情報も丸ごと入っています。手でコピーするときはアプリを終了してからにしてください。起動中にコピーすると、書き込みの途中の状態を掴むことがあります。

::: warning 消したら戻りません
アプリをアンインストールしても設定とキャッシュは残りますが、アプリデータフォルダごと削除すると蓄積したノートも消えます。サーバー側から取り直せるのは、サーバーにまだ残っているものだけです。
:::

## Misskey 側のデータ

自分の投稿・フォロー・お気に入りといった、サーバーに預けてあるデータのバックアップは Misskey 側の機能です。サーバーの設定画面からエクスポートしてください。NoteDeck のバックアップはあくまで「この端末の状態」を保存するものです。
