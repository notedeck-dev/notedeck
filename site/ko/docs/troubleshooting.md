# 문제 해결

문제가 생기면 먼저 **NoteDeck 정보** (NoteDeck について / About) 창의 "자체 진단" (自己診断)을 보세요. 스트림 끊김, 지난번의 비정상 종료, AI 별도 프로세스의 상태, HEARTBEAT의 연속 실패가 한곳에 표시됩니다. "정보 복사" (情報をコピー)로 보고용 정보를 얻을 수 있습니다.

## 로그인할 수 없음

서버의 호스트 이름을 입력합니다 (`misskey.io` 형태. `https://`나 끝의 `/`가 붙어 있어도 제거됩니다).

인증은 브라우저를 거칩니다. 브라우저에서 허용한 뒤 NoteDeck 쪽의 "인증했습니다" (認証しました)를 누를 때까지 완료되지 않습니다. 기본 브라우저가 열리지 않거나 도중에 어디까지 했는지 모르게 되었다면, "다시 하기" (やり直す)로 처음부터 다시 하세요.

Linux에서 Secret Service (GNOME Keyring 등)가 없는 환경에서는 실행할 때 그 사실을 알리는 경고가 표시되고, 토큰은 암호화 파일로 대피됩니다.

## 타임라인이 갱신되지 않음

NoteDeck은 서버와 WebSocket으로 항상 연결되어 있습니다. 회선이 끊기거나 절전 모드에서 복귀한 직후에는 다시 연결될 때까지 조금 시간이 걸립니다.

한동안 기다려도 흘러오지 않는다면:

1. **오프라인 모드**나 실시간 모드가 꺼져 있지 않은지 확인합니다 (트레이 메뉴에서도 전환할 수 있습니다)
2. "창을 숨기고 있는 동안 타임라인 구독을 중단" (ウィンドウを隠している間はタイムラインの購読を休止) 설정이 작동하고 있지 않은지 확인합니다
3. 칼럼을 직접 새로고침합니다
4. About의 자체 진단에서 연결 상태를 봅니다. 더 파고들려면 [개발자 모드](/ko/docs/#개발자-모드)에서 **스트림** (ストリーム) 칼럼을 열어 흐르고 있는 이벤트를 확인합니다

스트림 칼럼에는 실제로 주고받는 내용이 그대로 나오므로, "서버에서 오지 않는" 것인지 "앱이 표시하지 않는" 것인지 구분할 수 있습니다.

## 노트가 표시되지 않거나 갑자기 사라짐

표시되지 않는 이유는 몇 가지가 있습니다.

- **뮤트에 걸렸습니다** — 단어, 유저, 서버, 리노트 뮤트 설정을 확인하세요
- **칼럼 쿼리로 거르고 있습니다** — 칼럼의 필터 메뉴에서 적용 중인 쿼리를 확인하세요
- **작성자가 정지되었습니다** — 서버에서 정지된 유저의 노트는 숨겨집니다. 정지가 풀리면 자동으로 돌아옵니다

NoteDeck은 데이터를 지우지 않고 "표시할지 말지"만 판단합니다. 뮤트를 해제하면 숨겨져 있던 노트가 그대로 돌아옵니다.

## 이미지가 나오지 않음 / 외부 연동을 쓸 수 없음

실행할 때 "이미지 중계와 외부 연동 (HTTP API)을 쓸 수 없습니다" (画像の中継と外部連携 (HTTP API) を使えません)라고 표시되면, NoteDeck이 쓰는 로컬 포트를 다른 앱이 먼저 차지하고 있습니다. 그 앱을 멈추거나 포트를 비운 뒤 NoteDeck을 다시 실행하세요.

## 외관이 깨짐

`custom.css`를 쓰고 있다면 먼저 그 내용을 비우고 확인하세요. 앱 업데이트로 내부 구조가 바뀌면, 예전에 쓴 CSS가 의도하지 않은 곳에 적용될 수 있습니다.

테마가 원인일 때도 있습니다. 기본 테마로 되돌려서 원인을 좁혀 보세요.

## 동작이 무거움

- 열려 있는 칼럼 수를 줄입니다 ([프로파일](/ko/docs/deck/profiles)로 용도별로 나누기)
- [표시의 가벼움](/ko/docs/guide/appearance#표시의-가벼움-고르기)을 메모리 절약 쪽 프리셋으로 바꿉니다
- 이미지가 많은 칼럼을 닫습니다

## AI가 응답하지 않음

- API 키가 유효한지, 프로바이더 쪽 잔액이 남아 있는지
- 에이전트 설정에서 프로바이더가 선택되어 있는지
- 필요한 조작이 권한으로 금지되어 있지 않은지 (확인 대화 상자를 닫아 버리지 않았는지)
- AI 별도 프로세스가 동작하고 있는지. About의 자체 진단에 자식 프로세스 종료, 버전 불일치, 상주가 동작하지 않음 같은 이유가 표시됩니다. 자세한 내용은 [AI 별도 프로세스](/ko/docs/notemaid#문제가-생겼을-때)

HEARTBEAT가 연속으로 실패하면 자동으로 멈추고 경고가 나옵니다. 원인을 고친 뒤 다시 활성화하세요.

## 설정을 초기 상태로 되돌리고 싶음

해당하는 [설정 파일](/ko/docs/config/files)을 삭제하면 다음 실행 때 기본값으로 다시 만들어집니다. 전부 되돌리고 싶다면 설정 폴더를 통째로 삭제하세요.

::: warning 먼저 백업하세요
설정 폴더를 지우면 메모, AI의 인격과 기억, AI 세션, 스킬, 플러그인, 테마도 함께 사라집니다. 먼저 [백업](/ko/docs/config/backup)을 해 두세요. 쌓아 둔 노트 (`notecli.db`)는 설정 폴더의 상위에 있으므로 남습니다.
:::

## 그래도 해결되지 않을 때

[GitHub Issues](https://github.com/notedeck-dev/notedeck/issues)에 보고해 주세요. 다음 정보가 있으면 원인을 찾기 쉬워집니다.

- OS와 앱 버전
- 무엇을 하면 일어나는지
- About의 자체 진단에 있는 "정보 복사" (情報をコピー)의 내용 (비정상 종료 뒤에는 "진단 로그를 복사해서 보고" (診断ログをコピーして報告))
- 로그 (**파일 → 로그 폴더 열기** (ファイル → ログフォルダを開く). AI 별도 프로세스의 로그는 앱 데이터 폴더의 `logs/`)
