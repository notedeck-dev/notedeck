# 문제 해결

## 로그인할 수 없음

서버의 호스트 이름만 입력했는지 확인하세요 (`https://`는 필요 없으며, `misskey.io` 형태).

인증은 브라우저를 거칩니다. 기본 브라우저가 열리지 않거나, 허용한 뒤 NoteDeck으로 돌아오지 않는다면 앱을 한 번 다시 시작한 뒤 다시 시도하세요.

## 타임라인이 갱신되지 않음

NoteDeck은 서버와 WebSocket으로 항상 연결되어 있습니다. 회선이 끊기거나 절전 모드에서 복귀한 직후에는 다시 연결될 때까지 조금 시간이 걸립니다.

한동안 기다려도 흘러오지 않는다면:

1. 칼럼을 직접 새로고침합니다
2. **스트림** (ストリーム) 칼럼을 열어 연결 상태와 흐르고 있는 이벤트를 확인합니다

스트림 칼럼에는 실제로 주고받는 내용이 그대로 나오므로, "서버에서 오지 않는" 것인지 "앱이 표시하지 않는" 것인지 구분할 수 있습니다.

## 노트가 표시되지 않거나 갑자기 사라짐

표시되지 않는 이유는 몇 가지가 있습니다.

- **뮤트에 걸렸습니다** — 단어, 유저, 서버, 리노트 뮤트 설정을 확인하세요
- **칼럼 쿼리로 거르고 있습니다** — 칼럼의 필터 메뉴에서 적용 중인 쿼리를 확인하세요
- **작성자가 정지되었습니다** — 서버에서 정지된 유저의 노트는 숨겨집니다. 정지가 풀리면 자동으로 돌아옵니다

NoteDeck은 데이터를 지우지 않고 "표시할지 말지"만 판단합니다. 뮤트를 해제하면 숨겨져 있던 노트가 그대로 돌아옵니다.

## 외관이 깨짐

`custom.css`를 쓰고 있다면 먼저 그 내용을 비우고 확인하세요. 앱 업데이트로 내부 구조가 바뀌면, 예전에 쓴 CSS가 의도하지 않은 곳에 적용될 수 있습니다.

테마가 원인일 때도 있습니다. 기본 테마로 되돌려서 원인을 좁혀 보세요.

## 동작이 무거움

- 열려 있는 칼럼 수를 줄입니다 ([프로파일](/ko/docs/deck/profiles)로 용도별로 나누기)
- [표시의 가벼움](/ko/docs/guide/appearance#표시의-가벼움-고르기)을 메모리 절약 쪽 프리셋으로 바꿉니다
- 이미지가 많은 칼럼을 닫습니다

## AI가 응답하지 않음

- API 키가 유효한지, 프로바이더 쪽 잔액이 남아 있는지
- AI 설정에서 프로바이더가 선택되어 있는지
- 필요한 조작이 권한으로 금지되어 있지 않은지 (확인 대화 상자를 닫아 버리지 않았는지)

HEARTBEAT가 연속으로 실패하면 자동으로 멈추고 경고가 나옵니다. 원인을 고친 뒤 다시 활성화하세요.

## 설정을 초기 상태로 되돌리고 싶음

해당하는 [설정 파일](/ko/docs/config/files)을 삭제하면 다음 실행 때 기본값으로 다시 만들어집니다. 전부 되돌리고 싶다면 설정 폴더를 통째로 삭제하세요.

::: warning 먼저 백업하세요
설정 폴더를 지우면 쌓아 둔 노트 캐시와 메모도 함께 사라집니다. 먼저 [백업](/ko/docs/config/backup)을 해 두세요.
:::

## 그래도 해결되지 않을 때

[GitHub Issues](https://github.com/notedeck-dev/notedeck/issues)에 보고해 주세요. 다음 정보가 있으면 원인을 찾기 쉬워집니다.

- OS와 앱 버전
- 무엇을 하면 일어나는지
- 로그 (**파일 → 로그 폴더 열기** (ファイル → ログフォルダを開く))
