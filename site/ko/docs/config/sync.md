# Git이나 Dropbox로 설정 옮기기

NoteDeck의 설정은 앱 데이터 폴더 안의 **`config/`** 한 곳에 모여 있습니다. 이 폴더 하나가 "옮기는 단위"입니다. Git으로 이력을 남겨도, Dropbox 등으로 다른 PC와 맞춰도, dotfiles 매니저로 관리해도 괜찮습니다.

`config/` 바깥에 있는 것 (노트 캐시, AI의 대화, 창 위치, 동의와 키의 유무)은 옮기는 것이 아니므로 동기화 대상으로 삼지 마세요. 무엇이 어디에 있는지는 [설정 파일](/ko/docs/config/files#설정은-어디에-있나)에 있습니다.

::: warning 공개하지 마세요
`config/`에는 어느 계정을 어느 칼럼에서 보고 있는지 (`user@host`), 외부 서비스의 URL, 실행되는 코드 (플러그인 / 위젯 / 스킬), AI와 플러그인에 허용한 조작이 들어 있습니다. API 키와 액세스 토큰은 들어 있지 않지만, **공개 저장소에 두기 위한 형태가 아닙니다**. Git에 넣는다면 비공개 저장소에 두세요.
:::

## 전제

- **앱과 상주하는 AI를 종료한 뒤에 바깥에서 고치세요.** `git pull`, 외부 에디터 편집, 동기화 소프트웨어의 되쓰기는 앱을 닫은 동안에 끝내세요. 앱은 설정 파일의 외부 변경을 지켜보지 않으므로, 연 채로 고치면 다음 조작에서 앱 쪽 사본이 덮어써서 변경이 사라집니다. 상주하는 AI (notemaid)가 돌고 있으면 `ai.json5`를 되쓸 수 있으니 그것도 멈추세요.
- **다시 저장하면 주석은 사라집니다.** 설정 파일은 JSON5라서 주석을 쓸 수 있지만, 앱이 다시 저장하면 주석은 남지 않습니다.
- **쓰기는 결정적입니다.** 같은 내용이면 같은 바이트열이 되고, 실행만 하거나 읽기만 해서는 파일을 다시 쓰지 않습니다. Git 차이가 "건드리지 않았는데 늘어나는" 일은 없습니다.

## Git으로 관리하기

```bash
cd ~/.local/share/com.notedeck.desktop/config   # macOS / Windows의 위치는 「설정 파일」 참조
git init
git add .
git commit -m "NoteDeck 설정"
```

`.gitignore`는 NoteDeck이 (없으면) 둡니다. `config/` 안은 설정뿐이므로 제외하는 것은 쓰는 도중의 임시 파일뿐입니다.

### 다른 PC에서 쓰기

1. 새 PC에서 NoteDeck을 한 번 실행하고 종료합니다 (앱 데이터 폴더가 생깁니다).
2. `config/` 안을 비우고 거기에 저장소를 clone합니다 (또는 clone한 폴더를 `config`라는 이름으로 둡니다).
3. NoteDeck을 실행하고 같은 계정으로 로그인합니다.

칼럼은 `user@host`로 계정을 가리키므로 로그인한 시점에 그 PC의 계정에 다시 묶입니다. 아직 로그인하지 않은 계정의 칼럼은 "계정 미연결"로 남고, 로그인하면 연결됩니다.

외부 서비스 연결 (AI 제공자 등)은 **정의만** 옮겨집니다. API 키와 "AI에게 보이기 / 외부 앱에 보이기" 동의는 그 PC의 상태이므로, 쓰려고 할 때 설정 화면이 요구합니다.

### dotfiles 매니저

- **chezmoi**처럼 파일을 **복사**해서 배치하는 도구는 그대로 쓸 수 있습니다.
- **GNU stow**처럼 파일 단위로 **심볼릭 링크**를 거는 도구도 쓸 수 있습니다. NoteDeck은 링크를 설정으로 읽고, 저장은 링크가 가리키는 곳에 씁니다 (링크를 실제 파일로 바꾸지 않습니다).

## Dropbox 등 동기화 폴더에 두기

`config/` 전체, 또는 `config/profiles/` 같은 일부를 동기화 폴더로 옮기고 심볼릭 링크로 원래 자리에 되돌립니다.

```bash
# 예: 프로파일만 Dropbox로
mv ~/.local/share/com.notedeck.desktop/config/profiles ~/Dropbox/notedeck-profiles
ln -s ~/Dropbox/notedeck-profiles ~/.local/share/com.notedeck.desktop/config/profiles
```

- **쓰는 PC는 한 번에 한 대.** 두 대에서 동시에 NoteDeck을 열고 같은 폴더에 쓰면 나중에 쓴 쪽이 이깁니다. 동기화 소프트웨어가 "충돌 사본"을 만들면 같은 id를 가진 파일이 둘이 되므로, NoteDeck은 뒤에 오는 쪽을 건너뛰고 토스트로 알립니다. 어느 쪽을 남길지 정하고 다른 쪽을 지우세요.
- **`data/` (AI의 대화와 메모)는 동기화 폴더로 향하게 하지 마세요.** 다른 사람의 글 본문 (팔로워 한정과 DM 포함), 아직 올리지 않은 초안, AI가 당신에 대해 기억한 것이 들어 있습니다. 암호화되지 않는 클라우드에 둘 것이 아닙니다.
- **`state/` `cache/` `notecli.db`는 동기화하지 마세요.** 이 PC의 상태와 캐시입니다. `notecli.db`는 SQLite라서 쓰는 도중을 동기화하면 깨집니다.

## 오래된 버전에서 업데이트했을 때

이전에는 설정이 `notedeck/`라는 폴더에 있었습니다. 업데이트 후 첫 실행에서 NoteDeck이 `config/` `data/` `state/` `cache/`로 나눕니다. 옮기기 전의 내용은 앱 데이터 폴더의 `backups/pre-layout-<일시>/`에 사본을 남깁니다 (얼마 뒤 지워집니다).

`notedeck/` 자체를 심볼릭 링크로 두고 동기화하던 경우, NoteDeck은 내용을 끄집어내지 않습니다 (동기화 대상에서 사라져, 옛 버전을 그대로 쓰는 다른 PC의 설정까지 사라지기 때문). 실행 시 그 취지의 알림이 나오므로, 동기화 대상 안을 `config`와 `data`로 나눈 뒤 `config/`와 `data/`로 링크를 다시 걸고 재시작하세요.
