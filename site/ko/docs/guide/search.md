# 노트 찾기

NoteDeck의 검색에는 두 계층이 있습니다.

| | 찾는 곳 | 찾을 수 있는 것 |
|---|---|---|
| **서버 검색** (サーバー検索) | Misskey 서버 | 서버가 검색 대상으로 삼는 노트 |
| **클라이언트 검색** (クライアント検索) | 손안의 데이터베이스 | 내 화면에 흘러온 노트 (모든 서버, 모든 계정을 넘나들며) |

"분명히 봤는데 찾을 수 없다"는 대부분 서버 쪽 검색 대상에서 빠진 경우입니다. NoteDeck은 표시한 노트를 손안에도 쌓아 두므로, 거기서 찾을 수 있습니다. 둘 다 칼럼으로 열 수 있고, 나란히 놓고 쓸 수 있습니다.

## 클라이언트 검색 칼럼

"클라이언트 검색" 칼럼은 손안에 쌓인 노트를 서버와 계정을 넘나들며 한꺼번에 찾습니다. 어느 서버에서 봤는지 기억하지 못해도 찾을 수 있습니다.

- 검색어 외에도 범위 (전체 / 특정 서버 / 특정 계정), 작성자 (`name` 또는 `name@host`), 기간, 첨부 유무로 좁힐 수 있습니다
- 검색어가 비어 있어도 조건만으로 찾을 수 있습니다. "최근 1주일, 이미지 첨부" 같은 조건도 만들 수 있습니다
- 검색어와 조건은 칼럼에 저장되므로, 조건을 둔 채로 계속 열어 둘 수 있습니다
- 여러 서버에서 본 같은 노트는 한 줄로 묶이며, 어느 서버에서 봤는지는 줄의 내역에서 확인할 수 있습니다
- 서버에 로그인하지 않아도 손안에 있는 것은 찾을 수 있습니다

::: warning 채팅은 대상이 아닙니다
채팅 메시지는 서버 검색과 클라이언트 검색 어느 쪽으로도 검색할 수 없습니다.
:::

## 손안에 남는 구조

타임라인에 흘러온 노트는 로컬 SQLite에 자동으로 쌓입니다. 특별한 조작은 필요 없습니다. 얼마나 남길지는 설정의 캐시에서 고를 수 있습니다. 팔로워 전용이나 다이렉트를 포함해 내 눈을 거쳐 간 모든 노트가 암호화되지 않은 채 저장된다는 점은 기억해 두세요.

그래서 다음과 같은 일이 일어납니다.

- 서버에서 노트가 삭제되어도 손안의 사본은 남습니다
- 연합이 끊겨 상대 서버가 보이지 않게 되어도, 이미 가져온 노트는 읽을 수 있습니다
- 오프라인에서도 지난 타임라인을 다시 읽을 수 있습니다

::: warning 쌓이는 것은 "흘러온 것"뿐입니다
내가 한 번도 표시하지 않은 노트는 손안에 없습니다. 팔로우하지 않은 사용자의 과거 기록을 거슬러 올라갈 수는 없습니다.
:::

## 칼럼마다 시야 좁히기

검색과는 별도로 **칼럼 쿼리**라는 구조가 있습니다. 칼럼에 흘러오는 노트를 직접 쓴 조건식으로 걸러 낼 수 있습니다.

- 특정 키워드를 포함한 노트만 흘려보내기
- 특정 사용자나 서버의 노트를 빼기
- 첨부 파일이 있는 노트만 보기

조건은 AiScript 식으로 씁니다. 쓴 것은 이름을 붙여 저장할 수 있고, 여러 칼럼에서 돌려쓸 수 있습니다. 다른 사람이 쓴 쿼리를 [스토어](/ko/docs/guide/store)에서 설치할 수도 있습니다.

쿼리 관리는 "쿼리" (クエリ) 칼럼에서 하고, 적용은 타임라인 칼럼의 필터 메뉴에서 전환합니다.
